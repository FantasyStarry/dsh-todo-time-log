# 操作逻辑：三层单一入口

> 2026-11-06。本文记录「待办时间日志」面板的操作逻辑基线：为什么这样分层、每个动作的唯一控制点在哪、哪些取舍是刻意不做。改 UI 前先读一遍，避免又把入口摊平。

## 一句话

**按使用频次分三层，同类动作在全应用只保留一个控制点。**

| 层 | 用户意图 | 频率 | 唯一入口 |
| --- | --- | --- | --- |
| 捕获 | 想到一件事，记下来 | 最高 | 顶部 composer：输入框 +「添加」；属性靠 `#分类 @文件 !优先级 ^类型`，不靠表单 |
| 流转 | 看还剩什么，勾掉 / 改 / 删 | 次高 | 勾选圈（完成 + 撤销）、点标题（详情）、行尾「⋯」（详情 / 编辑 / 删除） |
| 复盘 | 这件事花了多久 | 低但差异化 | 表格完成时间列双行、看板卡片用时、甘特图生命周期、日历时间分布 |

## 已锁定的四条规则

1. **完成时间列双行**：已完成 = 完成时刻 +「用时 X」；未完成 = `-` +「进行中 X」（每 60s 随 `nowMs` 刷新）。不新增列，7 列结构不变。
2. **每行两个控制点**：勾选圈负责完成 / 取消完成（带 toast 撤销）；行尾「⋯」负责详情 / 编辑 / 删除。标题点击展开详情是快捷键，不是第二套入口。表格与看板同一套动作模型。
3. **一个捕获入口**：单条 composer 与批量对话录入共用同一位置，`批量` 是模式切换而不是第二个入口；页头不再放「对话录入」。导入 / 导出留在页头「数据」。
4. **删除 = 二次确认 + 撤销**：`⋯` → 删除先进入「确认删除 / 取消」，确认后 toast 提供撤销；撤销用 `/import`（merge）回插完整快照，id、创建时间、完成时间原样保留，不需要 Host 新增接口。

## 工具栏

固定两行，切视图不跳位：

- 第一行：视图分段（左）+ 搜索（右）。
- 第二行：当前视图专属控件（状态筛选 / 分组 + 密度 / 甘特范围 / 日历基准 + 月份导航）+ 分类、类型筛选（右）。
- 排序只保留表头点击：工具栏的「排序」下拉与升降序按钮是同一状态的第二个控制点，已删除。

## 明确不做

- **不做截止日期 / 逾期提醒**：产品定位是「记录」不是「计划」，加了会把操作逻辑拖回传统待办。
- **甘特 / 日历不承担流转操作**：它们是只读的时间视角，行内文字链只在紧凑视图保留。
- **看板卡片不加「详情」**：卡片已经是摘要（类型 / 优先级 / 分类 / 用时 / 文件），详情只在表格与甘特里需要。
- **不做批量完成 / 批量删除**：本地单机待办量级小，收益低于复杂度。

## 实现落点

| 文件 | 职责 |
| --- | --- |
| `src/client/panel.js` | 捕获区单条 / 批量切换、两行工具栏、删除撤销、`tableActionsId`、导入弹窗 `dirty` 透传 |
| `src/client/views/table.js` | 完成时间双行、行尾 `⋯` 菜单（详情 / 编辑 / 删除 + 确认态）、行内编辑补全优先级 / 类型 |
| `src/client/transfer.js` | 有文件 / 预览时遮罩与 Esc 不关闭（防手滑丢导入内容） |
| `src/client/styles.js` | 两行工具栏、用时副行、行内菜单、编辑态选择器 |
| `test/ui/panel.test.mjs` | 用时双行、⋯ 菜单删除 + 撤销、批量模式、导入防误关 |
