# 看板改版方案（六期 P0 + 七期 A/B/C + 八期类型）与后续路线

> 结论先行：看板的问题不是「缺拖拽」，而是**卡片和列头浪费了信息层级**。六期先做零数据模型改动的 P0（读与找），把「待办 + 时间日志」的产品差异点（用时/已进行）放到卡片上；七期完成 A（移动/泳道/快捷键/密度）、B（`priority` v4 数据模型）与 C（密度与时长微调）；八期补 `type`（缺陷/新功能/改进/疑问/杂项/其他，v5）与类型筛选/搜索；`dueAt`/`order`/多值 tags/指针拖拽仍留作后续。
>
> 依据：[`docs/research/kanban-design-research.md`](../research/kanban-design-research.md)（15 个模式 + 来源）与 [`docs/research/kanban-current-state.md`](../research/kanban-current-state.md)（代码/门禁现状、R1–R12、Q1–Q8）。

---

## 1. 设计原则（本轮遵循）

1. **卡片是索引，不是详情页**：只保留「识别 + 判断」所需信息；完整属性进详情/更多操作。
2. **列 = 字段的投影**：改列 = 改 `status`/`project`，不引入 `columnId`/`boardOrder`。
3. **一个主操作 + 一个更多**：完成是唯一常驻操作；编辑/删除按需展开，且不依赖 hover（WCAG 2.5.8）。
4. **颜色只是辅助**：状态点/徽标必须配文字；只用 `--dsw-alias-*` token + `color-mix()`。
5. **先读、再找、后移动**：拖拽不是第一优先级；两列板上拖拽 ≈ 点完成，且 WCAG 2.5.7 要求单指针替代。

## 3. 明确不做的事

| 不做 | 原因 | 替代 |
| --- | --- | --- |
| 指针拖拽（P0/P1） | 两列状态板拖拽 ≈ 点完成；WCAG 2.5.7 还要求单指针替代；拖拽+键盘+菜单三套成本高 | 「更多 → 移动到…」菜单（P1）；将来再做 HTML5 DnD 增强 |
| WIP 限制 | 个人待办没有多阶段工作流可约束；硬上限会拒绝「记录想法」 | 已完成列收纳（最近 10 条/折叠） |
| 完成列无限增长方案 | — | 已做「默认最近 10 条 + 显示全部」 |
| `tags` / 自定义工作流列 | 与 `project`、`files` 重叠；会推翻「待办 + 时间日志」语义并牵连四视图/统计/工具契约 | 泳道 + 现有两个字段 |
| 每项目一色 | token 没有无限色板，颜色一多就无语义，暗色对比度难保证 | 项目只用「中性点 + 名称」 |

## 4. P1 落地情况（七期 A）

已落地：移到分类（`project`，带撤销）、状态 × 分类泳道、`/`/`n`/`f` 快捷键、舒适/紧凑密度。仍可继续但收益递减：

- **roving tabindex**：方向键在列内卡片间移动、`Home/End` 到首尾，可把每卡 2 个 tab stop 再降为「列 1 个停靠点」；需要卡片 ref 数组与焦点环样式。
- **`E` 编辑 / `Esc` 关闭** 等每卡快捷键。
- **状态分组下的「移到已完成/未完成」菜单项**：目前由 checkbox 承担单指针替代，可加但非必需。

## 5. P2 落地情况与剩余

已落地：`priority`（v4 数据模型，`store` 迁移 + `/list` 排序 + 工具 schema + quick-add 标记 + UI 徽标/编辑/排序）与 `type`（v5，类型徽标/编辑/筛选/搜索 + `^` 标记）。

剩余：

- `dueAt`：卡片「今天/逾期 N 天」+ 看板排序；必须先统一日历/甘特的时间语义（当前日历按创建或完成落格）。
- `order`（手动排序）：仅 `sortBy='manual'` 时允许置顶/拖动；与排序互斥（单一状态源）。
- 多值 `tags`：当前 type 是单值枚举；若需要一条待办多个自由标签再考虑 v6（多选 chips + 筛选/搜索/契约同步）。
- 指针拖拽增强：HTML5 DnD，但必须保留「移到分类」菜单与键盘路径。
- 迁移风险：v5 对旧版插件是「不支持版本」（会归档重建）——发布前确认没有旧 Host 共存；后续每次加字段都要同步 `store.js` 迁移、`/list` 排序、工具 schema、README 契约与测试。

## 6. 验收与门禁

- 只用 `React.createElement`；无新依赖；仅 `require('react')`。
- 颜色只用 `--dsw-alias-*` + `color-mix()`；类名 `ttl-` 前缀；i18n zh/en 成对、占位符一致、无未使用 key（`test/client-audit.mjs` 会失败）。
- 不查询 DOM；焦点用 ref + `.focus()`；菜单/操作区关闭用 `onBlur`/`Escape`，不加 document 监听。
- 键盘可达：所有鼠标操作有键盘路径；焦点可见；状态变化有 toast 或 `role="status"`。
- 窄屏（≤560px）与暗色主题目检；空态/加载/错误三态不混淆。
- 改完跑：`node --check lib/client.js`、`npm test`、`npm run audit`；用 `docs/preview/` 的静态渲染流程补图对照。
